## 利用者向け文書の基準(README.md と、docs/ 配下などの利用者向けの文書)

読み手は、このソフトウェアを使う人です。実装は読みません。

### 書かないもの

3. mechanism: 読み手に不要な内部の実装(関数名・内部で使う API の呼び方・比較方法・どのジョブが何を呼ぶか)
4. deployment: ソフトウェアが要求しない、特定の外部サービスや公開手段の選び方・設定手順(トンネル、ホスティング、プロキシの選択など)
5. copy: 正本(`--help` の出力、スキーマ、設定ファイルのひな形、外部サービスの公式ドキュメント)にある内容の書き写し(オプション・設定項目・環境変数・API の一覧、外部サービスの画面操作の手順など)。正本の場所を指す一文は copy ではない

### 書いてよいもの

共通の「書かないもの」と、上の 3〜5 のどれにも当てはまらないものだけです。

- 読み手が実行するコマンド、設定するパスや変数名、待ち受けるアドレス
- 設定項目・API エンドポイントが何であるかを示す一文(既定値と必須条件を含んでよい)
- 使い始める前に読み手が用意するもの(トークンの権限、アカウント、外部サービス側で既定から変える設定値)と、それぞれがどの機能に要るか
- 読み手の操作手順と、その操作の結果として読み手に見えるもの
- 読み手に見える制限(何ができない・何が不正確になるか)と、その原因になっている外部の事実。内部の仕組みを残している理由は制限ではない
