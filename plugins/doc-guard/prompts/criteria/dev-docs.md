## 開発者向け文書の基準(docs/development.md、CONTRIBUTING.md など)

読み手は、開発に参加する人です。コードは読めます。

### 書かないもの

3. mechanism: コードを読めば分かる関数単位の実装(関数名・内部で使う API の呼び方・比較方法・どのジョブが何を呼ぶか)
4. copy: 正本(`--help` の出力、スキーマ、設定ファイルのひな形、外部サービスの公式ドキュメント)にある内容の書き写し。正本の場所を指す一文は copy ではない

### 書いてよいもの

共通の「書かないもの」と、上の 3・4 のどれにも当てはまらないものだけです。

- 技術スタック、モジュールの責務
- 開発用のコマンド、テストの手順と、その結果として読み手に見えるもの
