# コメントと文書の基準

共通の基準と、書くファイルの種類に合う基準に従います。

<!-- criteria: common -->

## 共通の基準(すべての項目)

このリポジトリの方針は「必要最小限しか書かない」です。

読み手は、このリポジトリを今初めて読む人です。変更前の状態も、変更した人の考えも知りません。

### 書かないもの

- history: 次のどれか
   - 変更前の状態・移行・変更の事実に触れている(「以前は」「現在は」「〜に変更」「〜から〜へ」「不要になりました」「v2 から」「移行済み」「旧フォーマットがなくなったら」など)
   - 書き換えで、旧行の括弧書き・修飾語を別の語に入れ替えただけのもの(例: 旧「(X)」→ 新「(Y)」)のうち、新しい語が実装の手段・取得元・内部の方式の名前であるもの。旧仕様との区別にしか役立たないので、消すのが正しい修正。新しい語が読み手から見える挙動や値(一致の仕方、上限、単位など)を表すなら、仕様の変更を反映したものなので history ではない
- rationale: なぜそうしたか・何を比べて選んだか・何のために残しているか(「〜ため」「保険として」「〜を防ぐために」で内部の設計を説明するもの)・調べて分かったこと・公式に記載がないこと・実測の結果・コストやクォータの試算

### 書いてよいもの

- ツールへの指示(eslint-disable、shellcheck、noqa など)とライセンス表記

## コメントの基準(ソースコードと設定ファイルのコメント)

読み手は、ソースコードのコメントならそのコードを変更する開発者で、コードそのものは読めます。設定ファイル(.env.example、設定のひな形など)のコメントならその設定を書く人です。

### 書かないもの

- restate: コメントが、隣のコードを読めば分かることを言い換えている(関数名・変数名・処理の手順の繰り返し、「〜を取得する」「〜を返す」「〜をインストールする」など)
- extra: 設定項目・環境変数・API・コマンドの説明で、「それが何か」「既定値」「必須になる条件」「読み手に見える制限」を超える補足(使われる箇所の列挙、例示の計算、内部の単位、呼び出し回数など)

### 書いてよいもの

共通の「書かないもの」と、上のどれにも当てはまらないものだけです。

- コードからは読み取れない外部の事実(外部 API・外部サービス・ファイル形式が返すデータや挙動)を述べ、それを知らないとコードを変更したときに壊すもの
- 設定項目が何であるかを示す一文(既定値と必須条件を含んでよい)

## 利用者向け文書の基準(README.md と、docs/ 配下などの利用者向けの文書)

読み手は、このソフトウェアを使う人です。実装は読みません。

### 書かないもの

- mechanism: 読み手に不要な内部の実装(関数名・内部で使う API の呼び方・比較方法・どのジョブが何を呼ぶか)
- deployment: ソフトウェアが要求しない、特定の外部サービスや公開手段の選び方・設定手順(トンネル、ホスティング、プロキシの選択など)
- copy: 正本(`--help` の出力、スキーマ、設定ファイルのひな形、外部サービスの公式ドキュメント)にある内容の書き写し(オプション・設定項目・環境変数・API の一覧、外部サービスの画面操作の手順など)。正本の場所を指す一文は copy ではない

### 書いてよいもの

共通の「書かないもの」と、上のどれにも当てはまらないものだけです。

- 読み手が実行するコマンド、設定するパスや変数名、待ち受けるアドレス
- 設定項目・API エンドポイントが何であるかを示す一文(既定値と必須条件を含んでよい)
- 使い始める前に読み手が用意するもの(トークンの権限、アカウント、外部サービス側で既定から変える設定値)と、それぞれがどの機能に要るか
- 読み手の操作手順と、その操作の結果として読み手に見えるもの
- 読み手に見える制限(何ができない・何が不正確になるか)と、その原因になっている外部の事実。内部の仕組みを残している理由は制限ではない

## 開発者向け文書の基準(docs/development.md、CONTRIBUTING.md など)

読み手は、開発に参加する人です。コードは読めます。

### 書かないもの

- mechanism: コードを読めば分かる関数単位の実装(関数名・内部で使う API の呼び方・比較方法・どのジョブが何を呼ぶか)
- copy: 正本(`--help` の出力、スキーマ、設定ファイルのひな形、外部サービスの公式ドキュメント)にある内容の書き写し。正本の場所を指す一文は copy ではない

### 書いてよいもの

共通の「書かないもの」と、上のどれにも当てはまらないものだけです。

- 技術スタック、モジュールの責務
- 開発用のコマンド、テストの手順と、その結果として読み手に見えるもの
